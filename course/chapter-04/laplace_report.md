# Laplace Mechanism Report

Generated by `laplace.py` (Chapter 4). Pure Python, standard library only. Synthetic dataset: 1,000 fictional residents, seed 7. Noise trials: 2,000 per epsilon value, seeds 123 and 456.

## Dataset

- Residents: 1000
- Borrowed a book this month: 451 (45.1%)
- Used the library wifi: 657

## Experiment 1: sensitivity (one person changes the answer by how much?)

- Counting query, true count: 451
- Flipping ONE person's answer changes the count by: 1
- Same query as an average: true average 0.451
- Flipping ONE person's answer changes the average by: 0.0010 (sensitivity 1/1000 = 0.001)

Sensitivity is the whole game: a count has sensitivity 1, an average over 1,000 people has sensitivity 0.001, so the average needs 1,000 times less noise for the same epsilon.

## Experiment 2: epsilon sweep on the counting query

Noise scale b = sensitivity / epsilon. Theory: mean absolute error = b, standard deviation = b * sqrt(2).

|---|---|---|---|---|---|---|
| 0.1 | 10.00 | 9.95 | 10.00 | 13.98 | 14.14 | 42.9% |
| 0.5 | 2.00 | 2.00 | 2.00 | 2.85 | 2.83 | 93.2% |
| 1.0 | 1.00 | 0.95 | 1.00 | 1.42 | 1.41 | 99.8% |
| 2.0 | 0.50 | 0.43 | 0.50 | 0.76 | 0.71 | 100.0% |
| 5.0 | 0.20 | 0.08 | 0.20 | 0.29 | 0.28 | 100.0% |

Read it as a trade: epsilon 0.1 gives strong privacy and a typical error of about 10 people on a count of a few hundred. Epsilon 5.0 gives a typical error under 1 person, and almost no privacy. The empirical numbers land on top of the theory, which is how you know the sampler is correct.

## Experiment 3: the same data as an average query

- Query: share of residents who borrowed a book, true value 45.1%
- Sensitivity: 0.001 (1/1000)
- Epsilon: 1.0
- Noise scale: 0.001
- Mean absolute error: 0.1011 percentage points (theory 0.1000)

At epsilon 1.0 the average is off by about a tenth of a percentage point. Averages over large groups are where differential privacy is nearly free, and that is why real deployments publish statistics, not raw rows.

## Experiment 4: what epsilon means in odds

Epsilon bounds the odds ratio: seeing the output can shift the odds that a given person is in the data by at most a factor of e^epsilon.

## Post-processing note

Every noisy count above was rounded to an integer and clamped into [0, 1000]. That costs no extra budget: anything you compute from an epsilon-DP output is still epsilon-DP. Clamping cannot leak, because it only uses the noisy output, never the raw data.
